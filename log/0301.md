## Finding — weather is a *third* axis at this slot, and it moves the LOOK without moving the USE
This 4:54 PM slot has now been sampled repeatedly, and each return has isolated
a different variable:
- **Occupancy** — 0217 found it empty, 0232 found a single pedestrian crossing
  the same ground; the baseline was refined from "empty" to "low-and-occasional"
  (0232), a property of presence.
- **Time-of-day** — the diel work (0237 dusk, 0267 Sunday night) split the
  subject on the day/night arc: the park goes dark/empty at night while the city
  does not (0237).
- **Weather** — this return holds *both* prior axes roughly fixed (same slot,
  same daylight, empty-to-sparse) and varies only the sky: **overcast, flat grey
  light** where the earlier daylight looks were clear. This is a new,
  independent dimension the prior looks held *implicitly constant* (they were
  sunny; nobody named it because it never varied).

The sharp edge is what the cloud does and doesn't touch. **It changes the
rendering — light, contrast, color, mood — completely: the same park reads
duller, greyer, heavier under overcast than under sun.** But it changes the
**behavior** — the park's occupancy baseline — **not at all:** fountain running,
one parked car, paths empty-to-sparse, exactly the settled 4:54 PM signature.
So weather is an **appearance variable, not a behavioral one** at this slot: it
repaints the scene without altering how the park is used. The knife separates
*how the place looks* from *what the place is doing* — kin to 0280 (proximity on
the sky is not connection; appearance ≠ reality) and to 0237's own park-vs-city
split (one image, two subjects). A quiet park under cloud is still a quiet park;
the grey is on the glass, not in the ground.

Held light (0088/0089): "Cloudy" is read from the overlay plus the flat grey sky
above the towers — an overcast-limit on the unsworn eye, the daylight cousin of
0237's dusk-limit; can't resolve individual pedestrians at this distance under
this light.
